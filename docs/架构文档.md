# 架构文档 — XHS 热点内容流水线

> 版本：v0.1 ｜ 状态：评审中 ｜ 更新：2026-09-07（同步书页式排版、GLM 模型层、concept 内容类型）

## 1. 设计原则

1. **最少成本原则**：v1 本地运行、GLM 跑量（`glm-5.3-flash`，可切换）、代码确定性排版成图，月成本 < 10 元；
2. **文档先行 + 可测试**：三件套文档同步维护，回归测试防行为漂移；
3. **领域配置化**：流水线核心与领域无关，领域差异全部进配置；
4. **人工闸门**：挑题、润色、发布三个环节必须人工确认，AI 不自动发布；
5. **事实铁律**：无源事实零容忍，`[待查证]` 机制贯穿成文与审核；
6. **可迁移**：v1 本地、v2 服务器，部署层独立于业务层。

## 2. 分层架构

```text
┌─────────────────────────────────────────────────────────────┐
│                    调度层（Windows 任务计划 / systemd）        │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│                     流水线核心（orchestrator）                │
│  hotspot: 采集 → 清洗合规拦截 → 探讨意义判断 → 闸门① → 调研    │
│           → 钢人化 → 成文                                    │
│  concept: 概念池取题 → concept_write（跳过采集/评估/调研）      │
│  两者 → 人工闸门②（润色） → 卡片化 → 书页成图 → 发布包 → 闸门③  │
└──┬──────────┬──────────┬──────────┬──────────┬─────────────┘
   ▼          ▼          ▼          ▼          ▼
数据源层    内容大脑    审核界面    成图层     通知层
(adapters)  (LLM 阶段)  (FastAPI)  (Chrome)  (PushPlus)
   │          │          │          │
   ▼          ▼          ▼          ▼
  AIHOT     GLM/       SQLite     flow_cards（书页排版，
  GitHub    DeepSeek   状态/数据    1080×1800，默认）
  (4源占位)  (可切换)              / render_cards（legacy 3:4）
```

### 各层职责

- **调度层**：按领域定时触发流水线；记录运行状态；失败重试与通知。
- **流水线核心**：编排各阶段，维护状态机与运行日志；与领域无关。
- **数据源层**：每个源一个适配器，实现统一接口，输出 `NormalizedItem`。
- **内容大脑**：LLM 阶段（评分/角度/调研/成文/概念成文/润色/卡片化），prompt 文件 + 领域配置；模型 provider 可切换。
- **审核界面**：手机 Web 界面，读写候选/草稿状态，提供批注与下载。
- **成图层**：书页式连续排版（`render/flow_cards.py`，默认）+ 旧单卡模板（`render/render_cards.py`，legacy）+ 无头 Chrome 截图。
- **通知层**：PushPlus 推送。

## 4. 领域配置 Schema

`domains/<id>/config.yaml`：

```yaml
id: ai-tools
name: AI 工具与效率
enabled: true
# content_type: hotspot   # 缺省 hotspot；concept 域显式声明 content_type: concept

schedule:
  time: "08:00"
  timezone: Asia/Shanghai
  candidates_ready_by: "08:30"

sources:                 # 启用的数据源与参数（未实现的源采集时自动跳过）
  - name: aihot
    params:
      mode: selected
      window: 24h
      extra_endpoints: ["hot-topics"]
      min_interval_seconds: 60
      use_etag_cache: true
  - name: github_trending
    params:
      keywords: ["ai", "agent", "llm", "mcp"]
      min_stars: 200
  # weibo_hot / zhihu_hot / toutiao_hot / baidu_hot 已注册但未实现

assess:
  weights: { heat: 0.30, controversy: 0.20, domain_match: 0.25, writable: 0.15, risk: 0.10 }
  min_score: 6.0          # 低于此分不成文
  candidate_budget: 10    # 每日候选上限
  daily_select_max: 2     # 建议最多选中条数
  risk_max_for_keep: 1    # risk 维度 >1 直接淘汰

llm:
  provider: glm
  model: glm-5.3-flash    # 备选：glm-4.6 / glm-4-flash / deepseek-chat（provider: deepseek）
  temperature: 0.6
  max_tokens: 32768       # write / concept_write 使用（思考型模型需覆盖推理消耗）
  budget_monthly: 30      # 月度告警阈值（元；告警推送尚未接线）

writing:
  min_length: 2800        # 全文字数契约（下限）
  max_length: 3500        # 全文字数契约（上限）
  title_max_chars: 20
  card_count_min: 5       # legacy 单卡模式参考值（flow 模式不使用）
  card_count_max: 7
  tone: apple-clean       # 预留
  # disclaimer: "…"       # concept 域使用：文末强制免责声明（如 money-basics）

cardify:                 # 书页式连续排版（docs/卡片排版规范.md）
  mode: flow             # flow = 书页连续排版；legacy = 旧单卡模板
  use_headings: true     # false = 散文模式（无节标题）
  section_count: 5       # 期望节数（4-7 之间浮动）
  canvas: { width: 1080, height: 1800 }
  layout:                # 键对应 render.flow_cards.Layout 字段，缺省用定稿值
    f_body: 42
    f_head: 50
    w_body: 600
    w_head: 800
    lh_body: 76
    para_gap: 30
    pad_top: 80
    pad_bottom: 120

compliance:
  block_categories: [politics, society-controversy, health, legal, finance-advice]
  block_keywords: []
  require_ai_label: true

notify:
  channel: pushplus
  events: [candidates_ready, draft_ready, budget_alert, pipeline_failed]  # 现仅 candidates_ready 已接线
  # review_url: "…"      # 候选就绪推送附带的审核链接
```

领域配置由 `pipeline/config.py` 加载（`DomainConfig`），所有阶段只读配置，不硬编码领域逻辑。concept 域（`ai-basics` / `money-basics`）差异：`content_type: concept`、`sources: []`（选题来自概念池）、无 `assess`/`angles`，`writing.disclaimer` 按需配置。

## 5. 数据模型（SQLite）

库文件：`data/pipeline.db`。

| 表 | 关键字段 | 说明 |
|---|---|---|
| `domains` | id, name, enabled, config_path, created_at | 领域注册表 |
| `candidates` | id, domain_id, date, source, source_item_id, title, summary, category, source_score, reason, url, assess_json, decision(pending/selected/rejected/edited/blocked), user_note, created_at | 候选池；`(domain_id, date)` 建索引；concept 模式取题后直接置 selected |
| `articles` | id, domain_id, candidate_id, title, status, angle, steelman_json, research_json, facts_json, todo_verify_json, body_json, version, created_at, updated_at | 文章与版本；status 现用 draft → packaged（polishing/confirmed/published 预留，界面查询兼容） |
| `article_feedback` | id, article_id, seq, scope(whole/range), range_start, range_end, text, applied_at | 用户批注 |
| `cards` | id, article_id, seq, kind, text, image_path | flow 模式 kind=cover/page（最终页面）；legacy 模式存单卡结构 |
| `packages` | id, article_id, path, size, created_at | 发布包 |
| `runs` | id, domain_id, date, stage, status(running/ok/failed), log, started_at, finished_at | 运行记录；超 6 小时 running 由 `sweep_stale_runs` 判定 failed |
| `settings` | key, value | 全局配置（预算、通知、开关） |
| `notifications` | id, event, channel, payload, status, sent_at | 通知记录 |

## 6. 状态机

```text
候选: pending → selected ─────────→ rejected（终态）
              │  └→ edited（人工改角度后视为 selected）
              ▼
文章: draft → polishing（用户批注）→ confirmed → packaged → published
              │（可回退：polishing ↔ draft 任意版本）
              ▼
       rejected（用户放弃该篇）
```

流水线阶段与人工闸门：

```text
hotspot: collect(含清洗/合规拦截) → assess ── 闸门① 用户挑题 ──→ research → steelman → write
         → 闸门② 用户润色确认 ──→ cardify(LLM 分节) → flow render(代码分页成图) ──→ package
         → 闸门③ 用户发布（v1 手动，v2 半自动停在确认按钮）

concept: 概念池取题 → concept_write ── 闸门② 用户润色确认 ──→ cardify → flow render ──→ package
```

## 7. 调度设计

- 每个启用领域一个调度项（v1：Windows 任务计划程序调用 `python scripts/run_daily.py --domain <id>`；concept 域调用 `python scripts/run_concept.py --domain <id>`）；
- 运行状态记录在 `runs` 表：超 6 小时仍 running 的运行由 `sweep_stale_runs` 判定为 failed（进程被杀/断电场景）；
- 重入锁（`data/<domain>.lock`）与 `data/logs/` 文件日志尚未实现；审核界面由 `scripts/ensure_web.py` 幂等拉起（日志 `data/web.log`）；
- 阶段间通过 SQLite 状态流转；闸门① 无选中候选时本次运行以 waiting_review 结束。

## 8. 部署设计

### v1（本地 Windows）

- Python 3.12 venv；`pip install -r requirements.txt`；
- 环境变量：`GLM_API_KEY`（现行三领域）、`DEEPSEEK_API_KEY`（备选 provider）、`PUSHPLUS_TOKEN`（`.env`，gitignore）；
- 审核界面：`uvicorn web.app:app --host 0.0.0.0 --port 8000`；
  - 同一 WiFi：手机访问 `http://<电脑局域网IP>:8000`；
  - 外出：cpolar/ngrok 免费隧道（可选）；
- 调度：Windows 任务计划程序，每日 08:00。

### v2（服务器迁移，约束已调研）

- 服务器：腾讯云轻量 43.138.158.123（4C4G，Ubuntu 22.04），现有 Java + MySQL 已占用大部分内存（曾有 OOM 记录，已加 2GB swap）；
- 部署约束：
  - Python 服务 systemd 单元，`MemoryMax=400M`，RSS 目标 < 300MB；
  - 独立 localhost 端口（如 9000），Caddy 子域名（如 `xhs.zhengxi.online`）反代 + HTTPS；
  - 数据用 SQLite，不引入 MySQL；
  - 成图 Chrome headless 内存开销大（峰值 300MB+），v2 先评估：低峰时段渲染或渲染放本地、成品包同步到服务器；
  - 公网仅 22/80/443，与现有安全基线一致；
- 迁移时只换部署层：代码、数据文件、领域配置整体搬移。

## 9. 合规与安全设计

- 敏感话题拦截在两处执行：采集入库前（`block_categories`/`block_keywords` 关键词与分类匹配，orchestrator 内联）+ assess 阶段（LLM 判定 risk，超阈值 verdict=blocked），命中即淘汰；
- 事实账本与 `[待查证]` 机制贯穿：write 阶段产出、审核界面高亮、发布包附清单；
- AI 标注：发布包内附发布提示（勾选 AI 参与创作），由用户发布时执行；
- 凭据：`.env`（gitignore），不入库不入文档；
- AIHOT 使用遵守其条款：匿名非商业免费；规模化变现前申请书面授权（记录在需求文档 NFR-2）。
