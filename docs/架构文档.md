# 架构文档 — XHS 热点内容流水线

> 版本：v0.1 ｜ 状态：评审中 ｜ 更新：2026-08-15

## 1. 设计原则

1. **最少成本原则**：v1 本地运行、DeepSeek 跑量、HTML 渲染成图，月成本 < 10 元；
2. **文档先行 + 可测试**：三件套文档同步维护，回归测试防行为漂移；
3. **领域配置化**：流水线核心与领域无关，领域差异全部进配置；
4. **人工闸门**：挑题、润色、发布三个环节必须人工确认，AI 不自动发布；
5. **事实铁律**：无源事实零容忍，`[待查证]` 机制贯穿成文与审核；
6. **可迁移**：v1 本地、v2 服务器，部署层独立于业务层。

## 2. 分层架构

```text
┌─────────────────────────────────────────────────────────────┐
│                    调度层（Windows 任务计划 / systemd）        │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│                     流水线核心（orchestrator）                │
│  采集 → 清洗归一化 → 探讨意义判断 → 人工闸门① → 调研 → 成文    │
│  → 人工闸门②（润色） → 卡片化 → 成图 → 发布包 → 人工闸门③      │
└──┬──────────┬──────────┬──────────┬──────────┬─────────────┘
   ▼          ▼          ▼          ▼          ▼
数据源层    内容大脑    审核界面    成图层     通知层
(adapters)  (LLM 阶段)  (FastAPI)  (Chrome)  (PushPlus)
   │          │          │          │
   ▼          ▼          ▼          ▼
  AIHOT     DeepSeek   SQLite     模板(domains/<id>/templates)
  微博/知乎   (可切换)   状态/数据    → 3:4 PNG
  头条/百度
  GitHub
```

### 各层职责

- **调度层**：按领域定时触发流水线；记录运行状态；失败重试与通知。
- **流水线核心**：编排各阶段，维护状态机与运行日志；与领域无关。
- **数据源层**：每个源一个适配器，实现统一接口，输出 `NormalizedItem`。
- **内容大脑**：LLM 阶段（评分/角度/调研/成文/润色/卡片化），prompt 文件 + 领域配置；模型 provider 可切换。
- **审核界面**：手机 Web 界面，读写候选/草稿状态，提供批注与下载。
- **成图层**：卡片 HTML 模板 + 无头 Chrome 截图。
- **通知层**：PushPlus 推送。

## 4. 领域配置 Schema

`domains/<id>/config.yaml`：

```yaml
id: ai-tools
name: AI 工具与效率
enabled: true

schedule:
  time: "08:00"          # 每日触发时间
  timezone: Asia/Shanghai

sources:                 # 启用的数据源与参数
  - name: aihot
    params:
      windows: ["selected:24h", "hot-topics"]
  - name: weibo_hot
    params: { keywords: ["AI", "人工智能", "大模型", "智能体"] }
  - name: zhihu_hot
    params: { section: tech }
  - name: toutiao_hot
    params: { category: tech }
  - name: baidu_hot
    params: {}
  - name: github_trending
    params: { language: "", keywords: ["ai", "agent", "llm"] }

assess:
  weights: { heat: 0.3, controversy: 0.2, domain_match: 0.25, writable: 0.15, risk: 0.1 }
  min_score: 6.0          # 低于此分不进候选池
  candidate_budget: 10    # 每日候选上限
  daily_select: 2         # 建议最多选中条数

llm:
  provider: deepseek
  model: deepseek-chat
  budget_monthly: 30      # 月度告警阈值（元）

writing:
  max_length: 800
  title_max_chars: 20
  card_count: "5-7"
  tone: apple-clean       # 对应模板与文风

compliance:
  block_categories: [politics, society-controversy, health, legal, finance-advice]
  block_keywords: []
  require_ai_label: true

notify:
  channel: pushplus
  events: [candidates_ready, draft_ready, budget_alert, pipeline_failed]
```

领域配置由 `pipeline/config.py` 加载，所有阶段只读配置，不硬编码领域逻辑。

## 5. 数据模型（SQLite）

库文件：`data/pipeline.db`。

| 表 | 关键字段 | 说明 |
|---|---|---|
| `domains` | id, name, enabled, config_path, created_at | 领域注册表 |
| `candidates` | id, domain_id, date, source, source_item_id, title, summary, category, source_score, reason, url, assess_json, decision(pending/selected/rejected/edited), user_note, created_at | 候选池；`(domain_id, date)` 建索引 |
| `articles` | id, domain_id, candidate_id, title, status(draft/polishing/confirmed/packaged/published), angle, steelman_json, research_json, facts_json, todo_verify_json, body, version, created_at, updated_at | 文章与版本 |
| `article_feedback` | id, article_id, seq, scope(whole/range), range_start, range_end, text, applied_at | 用户批注 |
| `cards` | id, article_id, seq, kind(cover/fact/opinion/case/takeaway), text, image_path | 卡片 |
| `packages` | id, article_id, path, size, created_at | 发布包 |
| `runs` | id, domain_id, date, stage, status, log, started_at, finished_at | 运行记录 |
| `settings` | key, value | 全局配置（预算、通知、开关） |
| `notifications` | id, event, channel, payload, status, sent_at | 通知记录 |

## 6. 状态机

```text
候选: pending → selected ─────────→ rejected（终态）
              │  └→ edited（人工改角度后视为 selected）
              ▼
文章: draft → polishing（用户批注）→ confirmed → packaged → published
              │（可回退：polishing ↔ draft 任意版本）
              ▼
       rejected（用户放弃该篇）
```

流水线阶段与人工闸门：

```text
collect → clean → assess ── 闸门① 用户挑题 ──→ research → write
        → 闸门② 用户润色确认 ──→ cardify → render ──→ package
        → 闸门③ 用户发布（v1 手动，v2 半自动停在确认按钮）
```

## 7. 调度设计

- 每个启用领域一个调度项（v1：Windows 任务计划程序调用 `python scripts/run_daily.py --domain <id>`）；
- 同一领域实例内部加锁（`data/<domain>.lock`），防止重入；
- 阶段间通过 SQLite 状态流转，中断可续跑（从失败阶段重试）；
- 运行日志写入 `runs` 表与 `data/logs/`。

## 8. 部署设计

### v1（本地 Windows）

- Python 3.12 venv；`pip install -r requirements.txt`；
- 环境变量：`DEEPSEEK_API_KEY`、`PUSHPLUS_TOKEN`（`.env`，gitignore）；
- 审核界面：`uvicorn web.app:app --host 0.0.0.0 --port 8000`；
  - 同一 WiFi：手机访问 `http://<电脑局域网IP>:8000`；
  - 外出：cpolar/ngrok 免费隧道（可选）；
- 调度：Windows 任务计划程序，每日 08:00。

### v2（服务器迁移，约束已调研）

- 服务器：腾讯云轻量 43.138.158.123（4C4G，Ubuntu 22.04），现有 Java + MySQL 已占用大部分内存（曾有 OOM 记录，已加 2GB swap）；
- 部署约束：
  - Python 服务 systemd 单元，`MemoryMax=400M`，RSS 目标 < 300MB；
  - 独立 localhost 端口（如 9000），Caddy 子域名（如 `xhs.zhengxi.online`）反代 + HTTPS；
  - 数据用 SQLite，不引入 MySQL；
  - 成图 Chrome headless 内存开销大（峰值 300MB+），v2 先评估：低峰时段渲染或渲染放本地、成品包同步到服务器；
  - 公网仅 22/80/443，与现有安全基线一致；
- 迁移时只换部署层：代码、数据文件、领域配置整体搬移。

## 9. 合规与安全设计

- 敏感话题拦截在 clean 与 assess 两处执行（关键词 + LLM 分类），命中即淘汰；
- 事实账本与 `[待查证]` 机制贯穿：write 阶段产出、审核界面高亮、发布包附清单；
- AI 标注：发布包内附发布提示（勾选 AI 参与创作），由用户发布时执行；
- 凭据：`.env`（gitignore），不入库不入文档；
- AIHOT 使用遵守其条款：匿名非商业免费；规模化变现前申请书面授权（记录在需求文档 NFR-2）。
