# 接口文档 — XHS 热点内容流水线

> 版本：v0.1 ｜ 状态：评审中 ｜ 更新：2026-08-15

## 1. 通用约定

- 数据格式：JSON（UTF-8）；
- 时间：ISO 8601，含时区（流水线默认 Asia/Shanghai）；
- 错误：统一 `{"error": {"code": "...", "message": "..."}}`；
- 审核界面 API 前缀：`/api`；
- 分页：`?limit=&cursor=`（cursor 原样回传，不跨查询）。

## 2. 数据源适配器接口

所有数据源实现统一基类：

```python
class SourceAdapter(ABC):
    name: str                    # 唯一标识，如 "aihot"
    domain_id: str               # 所属领域（适配器由领域配置实例化）

    def fetch(self, since: datetime) -> list[NormalizedItem]:
        """拉取该源的热点条目。"""

@dataclass
class NormalizedItem:
    source: str                  # 源标识
    source_item_id: str          # 源内唯一 ID
    title: str
    summary: str                 # 中文摘要（可为空）
    url: str                     # 原文链接
    category: str                # 分类（源未提供可为 ""）
    score: float | None          # 源自带评分（0-100），无则 None
    reason: str = ""             # 推荐理由（如 AIHOT 的 reason）
    published_at: datetime | None
    extra: dict = {}             # 源特有字段（如 AIHOT storyId、signal_count）
```

约束：
- 幂等：同一时间窗口重复调用返回可去重的数据（按 `source_item_id` 去重）；
- AIHOT：同端点轮询间隔 ≥ 60 秒；响应带 ETag，支持 304 缓存；
- 取数用 Python `requests`（本机 PowerShell `Invoke-WebRequest` 有 bug，不使用）。

## 3. 内容大脑（LLM 阶段）接口

每个阶段 = 一个 prompt 模板（`prompts/<stage>.md`，可被领域配置覆盖）+ 结构化输入/输出。

### 3.1 assess — 探讨意义判断

输入：

```json
{
  "domain": {"id": "ai-tools", "name": "AI 工具与效率"},
  "candidate": {"title": "...", "summary": "...", "category": "...", "score": 82, "reason": "...", "signals": 18},
  "weights": {"heat": 0.3, "controversy": 0.2, "domain_match": 0.25, "writable": 0.15, "risk": 0.1}
}
```

输出：

```json
{
  "total": 7.4,
  "dimensions": {"heat": 2, "controversy": 1, "domain_match": 2, "writable": 1, "risk": 1},
  "verdict": "worth_discussing",
  "one_line": "GLM-5.3 发布，工具型模型对个人工作流影响大，争议点在闭源 vs 开源",
  "suggested_angle": "普通人现在换掉手上的模型要花多少成本？",
  "risk_note": "无明显风险"
}
```

### 3.2 steelman — 角度设计（成文前）

输入：`{domain, candidate, research_summary?}`。

输出：

```json
{
  "strongest_for": "…（最强正方：支持/看好该热点的完整论证）",
  "strongest_against": "…（最强反方：质疑/反对的完整论证）",
  "chosen_angle": "…（最终切入角度）",
  "stance": "impartial",
  "empathy_point": "…（能引起读者共鸣的具体感受，不带立场）"
}
```

### 3.3 research — 内置调研（事实账本）

输入：`{domain, candidate, sources: [url...]}`（流水线提供 AIHOT story、原文链接、补充搜索）。

输出：

```json
{
  "facts": [
    {"claim": "GLM-5.3 于 2026-08 发布", "source": {"name": "AIHOT", "url": "..."}, "verified": true}
  ],
  "todo_verify": [
    {"claim": "相比上代推理速度提升 40%", "reason": "来源未明确给出该数字"}
  ],
  "key_insights": ["…", "…"],
  "controversies": [{"side_a": "…", "side_b": "…"}]
}
```

### 3.4 write — 成文

输入：`{domain, persona, angle_block, research_block, facts_json, todo_verify_json}`。

输出（结构化 JSON，非 Markdown 散文）：

```json
{
  "title": "GLM-5.3 发布后，普通人该换吗？（≤20 字符）",
  "body": [
    {"type": "hook", "text": "…"},
    {"type": "fact", "text": "…"},
    {"type": "opinion", "text": "…"},
    {"type": "case", "text": "…"},
    {"type": "takeaway", "text": "…"},
    {"type": "cta", "text": "…"}
  ],
  "tags": ["#AI工具", "#GLM", "#大模型"],
  "todo_verify": ["…"],
  "self_check": {"ai_flavor": "pass", "facts_intact": "pass"}
}
```

### 3.5 polish — 按批注润色

输入：`{article_body, feedback: [{scope, range_start, range_end, text}], facts_json}`。

输出：修改后的 `{title, body, tags}`（事实账本与 `todo_verify` 不可被修改，除非用户明确补充来源）。

### 3.6 cardify — 图文结构化（书页式连续排版）

write 产出的正文段落由 LLM 重组为分节结构，分页与成图由代码确定性完成（`render/flow_cards.py`，规范见 `docs/卡片排版规范.md`）。

输入：`{domain, body: [{type, text}...]}`。

输出：

```json
{
  "sections": [
    {"heading": "上线硅基流动，上下文 1M", "paragraphs": ["…", "…"]},
    {"heading": "…", "paragraphs": ["…"]}
  ]
}
```

约束：4-7 节；heading 为 8-14 字含信息量陈述句（中文数字编号由代码追加）；段落 80-200 字短段落节奏；不新增事实、不删除事实声明与待查证标注。

## 4. 审核界面 REST API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/domains` | 领域列表（含今日候选数、草稿数） |
| GET | `/api/today?domain_id=` | 今日候选 + 进行中文章摘要（审核界面首页） |
| GET | `/api/candidates?domain_id=&date=&limit=&cursor=` | 候选列表（含评分 JSON） |
| POST | `/api/candidates/{id}/decision` | 提交决策 `{decision: pending/selected/rejected/edited, note: "..."}` |
| GET | `/api/articles/{id}` | 文章详情（正文、角度、事实账本、待查证、批注历史） |
| POST | `/api/articles/{id}/feedback` | 提交批注 `{feedback: [{scope, range_start, range_end, text}]}` |
| POST | `/api/articles/{id}/polish` | 触发润色（按未应用批注调用 3.5） |
| POST | `/api/articles/{id}/confirm` | 确认定稿（进入卡片化） |
| GET | `/api/packages/{id}` | 下载成品包 zip |
| POST | `/api/candidates` | 人工补充候选 `{domain_id, title, url, note?}` |
| POST | `/api/runs/{id}/retry` | 重试失败的运行 |

决策接口示例：

```json
POST /api/candidates/12/decision
{"decision": "edited", "note": "角度改成：开源模型会不会让 AI 工具变成白菜价"}
```

## 5. 成图层接口

`render/flow_cards.py`（cardify.mode=flow，默认）：

```text
输入：domain_id, article_id, sections(JSON), title, layout(领域配置)
输出：data/output/<domain>/<article_id>/page_01.png ... page_N.png（1080×1800）
实现：sections → em 折行（避头尾）→ 行级连续分页 → HTML → Chrome headless 截图 → 内嵌 sRGB
```

`render/render_cards.py`（cardify.mode=legacy，旧单卡模板）：

```text
输入：domain_id, article_id, cards(JSON), template_id
输出：data/output/<domain>/<article_id>/card_01.png ... card_07.png（3:4）
实现：卡片 JSON → 注入 HTML 模板 → Chrome headless 截图（--window-size=1080,1440）
```

模板约定：领域可放 `domains/<id>/templates/card.html` 覆盖全局模板（缺省用 `render/templates/card.html`），用占位符 `{{kicker}}`、`{{body}}`、`{{seq}}`、`{{total}}`、`{{tag}}`；CSS 内联或同目录本地资源（Chrome 无头加载本地文件）。排版参数经领域配置 `cardify.layout` 覆盖（键同 `flow_cards.Layout` 字段）。

## 6. 发布包结构

```text
<domain>-<YYYYMMDD>-<article_id>/
├── images/          # page_01.png ... page_N.png（1080×1800）
├── publish.txt      # 标题 + 正文（含节标题，复制即用）
├── tags.txt         # 话题标签
└── 发布检查.md       # AI 标注提醒、待查证清单、来源列表
```

## 8. 模型层接口

`pipeline/llm/base.py`：

```python
class LLMProvider(ABC):
    def chat(self, prompt: str, system: str = "", json_mode: bool = True,
             temperature: float = 0.6) -> str | dict:
        ...
```

实现：`deepseek.py`（DeepSeek API，json_mode 用 response_format，模型名取领域配置 `llm.model`，缺省 `deepseek-chat`）；后续可加 `openai.py`，由领域配置 `llm.provider` 切换，调用方不感知。
