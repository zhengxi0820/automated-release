# 接口文档 — XHS 热点内容流水线

> 版本：v0.1 ｜ 状态：评审中 ｜ 更新：2026-09-07（同步书页式排版、GLM 模型层、concept 内容类型）

## 1. 通用约定

- 数据格式：JSON（UTF-8）；
- 时间：ISO 8601，含时区（流水线默认 Asia/Shanghai）；
- 错误：统一 `{"error": {"code": "...", "message": "..."}}`；
- 审核界面 API 前缀：`/api`；
- 分页：`?limit=&cursor=` 约定预留，当前列表接口未实现分页参数（`date` 过滤 + 全量返回）。

## 2. 数据源适配器接口

所有数据源实现统一基类：

```python
class SourceAdapter(ABC):
    name: str                    # 唯一标识，如 "aihot"
    domain_id: str               # 所属领域（适配器由领域配置实例化）

    def fetch(self, since: datetime) -> list[NormalizedItem]:
        """拉取该源的热点条目。"""

@dataclass
class NormalizedItem:
    source: str                  # 源标识
    source_item_id: str          # 源内唯一 ID
    title: str
    summary: str                 # 中文摘要（可为空）
    url: str                     # 原文链接
    category: str                # 分类（源未提供可为 ""）
    score: float | None          # 源自带评分（0-100），无则 None
    reason: str = ""             # 推荐理由（如 AIHOT 的 reason）
    published_at: datetime | None
    extra: dict = {}             # 源特有字段（如 AIHOT storyId、signal_count）
```

约束：
- 幂等：同一时间窗口重复调用返回可去重的数据（按 `source_item_id` 去重）；
- AIHOT：同端点轮询间隔 ≥ 60 秒；响应带 ETag，支持 304 缓存；
- 取数用 Python `requests`（本机 PowerShell `Invoke-WebRequest` 有 bug，不使用）。

## 3. 内容大脑（LLM 阶段）接口

每个阶段 = 一个 prompt 模板（`prompts/<stage>.md`，可被领域配置覆盖）+ 结构化输入/输出。

### 3.1 assess — 探讨意义判断

输入：

```json
{
  "domain": {"id": "ai-tools", "name": "AI 工具与效率"},
  "candidate": {"title": "...", "summary": "...", "category": "...", "source_score": 82, "reason": "...", "signal_count": "—"},
  "weights": {"heat": 0.3, "controversy": 0.2, "domain_match": 0.25, "writable": 0.15, "risk": 0.1}
}
```

输出：

```json
{
  "total": 7.4,
  "dimensions": {"heat": 2, "controversy": 1, "domain_match": 2, "writable": 1, "risk": 1},
  "verdict": "worth_discussing",
  "one_line": "GLM-5.3 发布，工具型模型对个人工作流影响大，争议点在闭源 vs 开源",
  "suggested_angle": "普通人现在换掉手上的模型要花多少成本？",
  "risk_note": "无明显风险"
}
```

### 3.2 steelman — 角度设计（成文前）

输入：`{domain, candidate(标题/摘要/推荐理由), angles 角度库}`。代码签名中的 `research` 参数当前未使用（钢人化只用候选信息与角度库）。

输出：

```json
{
  "strongest_for": "…（最强正方：支持/看好该热点的完整论证）",
  "strongest_against": "…（最强反方：质疑/反对的完整论证）",
  "chosen_angle": "…（最终切入角度）",
  "stance": "impartial",
  "empathy_point": "…（能引起读者共鸣的具体感受，不带立场）"
}
```

### 3.3 research — 内置调研（事实账本）

输入：`{domain, candidate}`。流水线组装 `materials` 注入提示词：AIHOT 摘要、推荐理由、story 事件综述与时间线（有 storyId 时）、原文节选（抓取正文前 4000 字）。

输出：

```json
{
  "facts": [
    {"claim": "GLM-5.3 于 2026-08 发布", "source": {"name": "AIHOT", "url": "..."}, "verified": true}
  ],
  "todo_verify": [
    {"claim": "相比上代推理速度提升 40%", "reason": "来源未明确给出该数字"}
  ],
  "key_insights": ["…", "…"],
  "controversies": [{"side_a": "…", "side_b": "…"}]
}
```

### 3.4 write — 成文

输入：`{domain_name, persona, steelman, facts_json, todo_verify_json, title_max_chars, min_length, max_length}`。调用时 `max_tokens` 取领域配置 `llm.max_tokens`（现行 32768）。

输出（结构化 JSON，非 Markdown 散文）：

```json
{
  "title": "GLM-5.3 发布后，普通人该换吗？（≤20 字符）",
  "body": [
    {"type": "hook", "text": "…"},
    {"type": "fact", "text": "…"},
    {"type": "opinion", "text": "…"},
    {"type": "case", "text": "…"},
    {"type": "takeaway", "text": "…"},
    {"type": "cta", "text": "…"}
  ],
  "tags": ["#AI工具", "#GLM", "#大模型"],
  "todo_verify": ["…"],
  "self_check": {"ai_flavor": "pass", "facts_intact": "pass", "no_fabricated_experience": "pass"}
}
```

约束：`body` 12-18 个段落（hook/cta 各 1 段，其余按内容归类型），每段 1-4 句、80-200 字；全文 `min_length`-`max_length` 字（现行 2800-3500）。代码侧有「禁止编造亲历」校验（`FABRICATED_PATTERNS`），命中时自动追加纠错指令重写一次。

### 3.5 polish — 按批注润色

输入：`{article_body, feedback: [{scope, range_start, range_end, text}], facts_json}`。

输出：修改后的 `{title, body, tags}`（事实账本与 `todo_verify` 不可被修改，除非用户明确补充来源）。

### 3.6 cardify — 图文结构化（书页式连续排版）

write 产出的正文段落由 LLM 重组为分节结构，分页与成图由代码确定性完成（`render/flow_cards.py`，规范见 `docs/卡片排版规范.md`）。

输入：`{domain, body: [{type, text}...]}`。

输出：

```json
{
  "sections": [
    {"heading": "上线硅基流动，上下文 1M", "paragraphs": ["…", "…"]},
    {"heading": "…", "paragraphs": ["…"]}
  ]
}
```

约束：4-7 节；heading 为 8-14 字含信息量陈述句（中文数字编号由代码追加）；段落 80-200 字短段落节奏；不新增事实、不删除事实声明与待查证标注。

### 3.7 concept_write — 概念科普成文（concept 类型）

跳过 collect/assess/research/steelman，从概念池取题后单次 LLM 调用成文。

输入：`{domain_name, persona, concept, title_max_chars, min_length, max_length, disclaimer_rule}`。`disclaimer_rule` 由领域配置 `writing.disclaimer` 生成（无配置时为「本领域无强制免责声明」）。调用时 `max_tokens` 取领域配置 `llm.max_tokens`。

输出：

```json
{
  "title": "越存越穷？一个借鸡蛋的故事（≤20 字符）",
  "body": [
    {"type": "hook", "text": "…"},
    {"type": "story", "text": "…"},
    {"type": "reveal", "text": "…"},
    {"type": "explain", "text": "…"},
    {"type": "extend", "text": "…"},
    {"type": "cta", "text": "…"}
  ],
  "tags": ["#…"],
  "self_check": {"zero_jargon": "pass", "story_logic": "pass", "fully_explained": "pass"}
}
```

约束：寓言式结构（hook 场景钩子 → story 寓言本体 3-5 段 → reveal 揭示（全文 40-50% 处）→ explain 讲透 → extend 克制延伸 → cta 互动）；零门槛（术语当场翻译、不编造精确数据）；篇幅按领域配置（概念域现行 2600-3400 字）。代码侧同样有「禁止编造亲历」校验与自动重写。

## 4. 审核界面 REST API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 审核界面页面（`web/static/app.html`） |
| GET | `/api/domains` | 领域列表（仅 enabled） |
| GET | `/api/today?domain_id=` | 今日候选 + 进行中文章摘要（审核界面首页） |
| GET | `/api/candidates?domain_id=&date=` | 候选列表（含评分 JSON；date 缺省为今天） |
| POST | `/api/candidates/{id}/decision` | 提交决策 `{decision: pending/selected/rejected/edited/blocked, note: "..."}` |
| GET | `/api/articles/{id}` | 文章详情（正文、事实账本、待查证、批注历史） |
| POST | `/api/articles/{id}/feedback` | 提交批注 `{feedback: [{scope, range_start, range_end, text}]}` |
| POST | `/api/articles/{id}/polish` | 触发润色（按未应用批注调用 3.5，version+1，状态回 draft） |
| POST | `/api/articles/{id}/confirm` | 确认并成图打包（cardify → 成图 → 发布包一次完成，调用 3.6 与 §5） |
| GET | `/api/packages/{id}/download` | 下载成品包 zip（FileResponse） |
| POST | `/api/candidates` | 人工补充候选 `{domain_id, title, url, note?}` |

决策接口示例：

```json
POST /api/candidates/12/decision
{"decision": "edited", "note": "角度改成：开源模型会不会让 AI 工具变成白菜价"}
```

## 5. 成图层接口

`render/flow_cards.py`（cardify.mode=flow，默认）：

```text
输入：domain_id, article_id, sections(JSON), title, layout(领域配置)
输出：data/output/<domain>/<article_id>/page_01.png ... page_N.png（1080×1800）
实现：sections → em 折行（避头尾）→ 行级连续分页 → HTML → Chrome headless 截图 → 内嵌 sRGB
```

`render/render_cards.py`（cardify.mode=legacy，旧单卡模板）：

```text
输入：domain_id, article_id, cards(JSON), template_id
输出：data/output/<domain>/<article_id>/card_01.png ... card_07.png（3:4）
实现：卡片 JSON → 注入 HTML 模板 → Chrome headless 截图（--window-size=1080,1440）
```

模板约定：领域可放 `domains/<id>/templates/card.html` 覆盖全局模板（缺省用 `render/templates/card.html`），用占位符 `{{kicker}}`、`{{body}}`、`{{seq}}`、`{{total}}`、`{{tag}}`；CSS 内联或同目录本地资源（Chrome 无头加载本地文件）。排版参数经领域配置 `cardify.layout` 覆盖（键同 `flow_cards.Layout` 字段）。

## 6. 发布包结构

zip 位于 `data/output/<domain>/<article_id>/<domain>-<article_id>-publish.zip`，内容：

```text
package/
├── images/          # page_01.png ... page_N.png（1080×1800；封面页 + 正文页）
├── publish.txt      # 标题 + 正文（含节标题，复制即用）
├── tags.txt         # 话题标签（空格分隔）
└── 发布检查.md       # AI 标注勾选提醒 + 待查证清单
```

## 8. 模型层接口

`pipeline/llm/base.py`：

```python
class LLMProvider(ABC):
    def chat(self, prompt: str, system: str = "", json_mode: bool = True,
             temperature: float = 0.6, max_tokens: int = 4096) -> str | dict:
        ...
```

实现：`deepseek.py`（DeepSeek API）、`glm.py`（智谱 BigModel API，OpenAI 兼容协议 + Bearer 鉴权，key 走 `GLM_API_KEY`；glm-4.5+/5.x 始终思考，`thinking: {type: enabled, effort: low}` 调档；JSON 模式参数不支持时按 response_format+thinking → 无 response_format → 无 thinking 三级降级，请求超时 900 秒；思考型模型注意 max_tokens 需覆盖推理消耗，write/concept_write 传领域配置 `llm.max_tokens`（现行 32768），其余阶段用默认 4096）、`fake.py`（测试用）。模型名取领域配置 `llm.model`，由领域配置 `llm.provider` 切换，调用方不感知。
