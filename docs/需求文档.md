# 需求文档 — XHS 热点内容流水线

> 版本：v0.1（第一版基线）｜ 状态：评审中 ｜ 更新：2026-08-15

## 1. 项目概述

### 1.1 背景

在小红书运营「AI 工具与效率」垂直账号，通过每日输出热点图文笔记获得流量与变现。AI 写作工具直接产出的内容有“AI 味”，且缺乏观点与共情；纯人工产出则供给不足。本项目用一条自动化流水线解决供给问题，同时保留人工审核与润色闸门，保证内容质量、观点与账号安全。

### 1.2 目标

- 每日自动发现热点、判断探讨价值、生成初稿、渲染图文卡片、产出可直接发布的成品包；
- 用户每天在手机上花约 5-10 分钟完成「挑题 → 润色 → 确认发布」；
- 流水线核心与领域配置分层，支持多领域共存（AI 工具、职场、理财等并行运行）；
- 第一版本地运行、成本极低（月成本 < 10 元），后续可迁移服务器。

### 1.3 成功标准（v1）

1. 连续 7 天自动产出每日候选（8-10 条），无人工干预爬取失败；
2. 用户完成挑选后，30 分钟内自动产出「正文草稿 + 卡片包 + 发布文案」；
3. 成文无编造事实；关键事实带来源或标 `[待查证]`；
4. 成品包（3:4 图片 + 标题 + 正文 + 标签）可直接在小红书 App 手动发布；
5. 回归测试库覆盖核心阶段，提示词/代码升级不破坏既有行为。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 领域（domain） | 一个账号定位，如 `ai-tools`（AI 工具与效率）。每个领域有独立配置、数据与调度 |
| 候选（candidate） | 一条可能值得写的热点 |
| 探讨意义判断 | 对候选进行五维评分，判断是否值得成文 |
| 事实账本 | 成文时登记每条关键事实及其来源，缺来源的进入 `[待查证]` 清单 |
| 成品包 | 图文卡片图片 + 标题 + 正文 + 标签 + 待查证清单，用于发布 |
| 审核界面 | 手机可访问的 Web 界面，用于挑题、批注、确认 |

## 3. 使用场景（每日闭环）

```
08:00  流水线自动运行：采集 → 清洗 → 探讨意义判断 → 候选池
08:30  微信推送通知：今日候选 8-10 条已就绪（附审核界面链接）
早上   用户在手机上挑 1-2 条（写/不写/改角度，可附批注）
白天   流水线对选中候选：内置调研 → 成文 → 卡片化 → 渲染成图
下午   微信推送通知：草稿与卡片已就绪
傍晚   用户在手机上逐条批注润色，确认
晚上   下载成品包，在小红书 App 手动发布
```

## 4. 功能需求

### FR-1 多领域共存（硬性约束）

- 流水线逻辑（采集、评分、成文、成图、发布包、调度、审核界面）与领域无关；
- 领域相关项全部配置化：数据源、角度库、人设文风、卡片模板、评分权重、合规清单；
- 多个领域可同时启用、独立调度、独立数据，互不干扰；
- 审核界面支持领域切换；
- **换领域 ≠ 放弃原领域**：新增领域只需新增配置目录与数据源适配器，原领域继续运行。

### FR-2 热点采集

- 主数据源：AIHOT（卡兹克 AI 热点站）匿名公开 API，免登录：
  - `hot-topics`：今日热点 Top10；
  - `items?mode=selected&window=24h`：精选资讯流（自带中文标题、摘要、分类、评分、来源、`reason` 推荐理由）；
  - `dailies/latest`：每日 AI 日报；
  - `stories/{id}`：单事件来龙去脉（调研阶段按需调用）。
- 补充数据源（v1 起）：微博热搜、知乎热榜、今日头条热榜、百度热搜、GitHub Trending（AI 相关）；
- 人工补充入口：用户在审核界面或通知通道可提交一条 URL/标题作为候选；
- v2：小红书站内搜索（需登录态，本地运行，控制频率）。

### FR-3 清洗与初筛

- AIHOT 数据视为已清洗（标题/摘要/分类/评分/reason 齐全），直接进入候选池；
- 补充源需归一化：去重（按标题/链接）、截断过长文本、过滤垃圾与广告、转 Asia/Shanghai 时区；
- 敏感话题自动拦截（见 NFR-2）。

### FR-4 探讨意义判断

- 对每条候选做五维评分（每维 0-2 分，总分 0-10）：
  1. 热度（信号源数量、AIHOT 评分、平台热度）；
  2. 争议度（是否有可讨论的分歧点，不失控为前提）；
  3. 领域匹配（与「AI 工具与效率」定位的相关度）；
  4. 可写性（能否用 3 段讲清楚、有角度可挖）；
  5. 风险（反向分：越敏感越高风险，高风险直接淘汰）。
- 评分权重来自领域配置，可调；
- 输出：候选 + 总分 + 各维得分 + 一句话推荐理由 + 建议角度（可选）。

### FR-5 人工审核（审核界面）

- 候选列表：标题、摘要、来源、评分、推荐理由、链接；
- 操作：`写` / `不写` / `改角度`（可填新角度或一句批注）；
- 草稿批注：对正文逐段批注或整篇给意见；
- 待查证清单高亮展示，用户可逐条「保留 / 删除 / 补充来源」；
- 确认：最终确认后进入成图与发布包环节；
- 界面必须手机友好（响应式、大按钮、少滚动）。

### FR-6 成文

- 内置调研：成文前抓取该热点 3-5 个信息源（AIHOT story、原文链接、补充搜索），形成事实账本；
- 事实账本：每条关键事实（数字、公司、人名、事件因果）绑定来源；缺来源标 `[待查证]`；
- 单次成文：一个 LLM 调用产出正文（v1，不跑多 Agent）；
- 写作要求：
  - 不偏不倚：事实层中立（steelman 最强正方/反方后选角度），不站队、不立场泄漏；
  - 共情：人性层有温度，允许「我同情但不站队」的复杂感受；
  - 活人感：像具体的人在说话，不编造亲历，不用翻案腔/冒号/破折号等 AI 腔（规则见成文 prompt 与领域配置）；
  - 小红书体：标题 ≤ 20 字符（UTF-16），正文 500-800 字，结尾带互动钩子；
- 输出为结构化 JSON（非 Markdown 散文），供审核界面与成图使用。

### FR-7 润色

- 用户批注后，流水线调用 LLM 按批注修改（保留事实账本不变）；
- 每次润色记录版本，可回退；
- 润色后重新做去 AI 味自检与事实复查。

### FR-8 成图（图文卡片）

- HTML/CSS 模板 + 无头 Chrome 截图，输出 3:4 卡片；
- 卡片构成：封面卡 + 事实卡/观点卡/案例卡/启示卡（共 5-7 张）；
- 风格：苹果风、简约清爽有美感（基于 apple-design-skill 设计规范）；
- 模板属于领域配置：换领域 = 换模板；
- 卡片文案由「卡片化」阶段从正文切分，每张卡文字量受模板约束；
- v2：AI 生图作为封面背景/装饰元素。

### FR-9 发布包与发布

- 成品包 = 3:4 图片（5-7 张）+ 标题 + 正文 + 话题标签 + 待查证清单，打包为 zip；
- 文案一键复制；
- v1：手动发布（用户在小红书 App 发布）；
- v2：半自动发布（浏览器自动化填表，停在确认按钮，用户点击发布）。

### FR-10 通知

- 通道：PushPlus 微信推送（免费、国内直连）；
- 时机：候选就绪（早 8:30）、草稿就绪（下午）、预算告警、流水线失败；
- 通知内容包含审核界面链接与一句话摘要。

### FR-11 调度

- 默认：每日 08:00 触发，08:30 前完成候选生成；
- 调度时间与启用领域均可配置；
- v1 用 Windows 任务计划程序；v2 迁服务器后改用 systemd timer / cron。

### FR-12 领域配置

每个领域一个配置目录 `domains/<id>/`：

```text
domains/<id>/
├── config.yaml        # 数据源、评分权重、调度、成本上限、合规清单
├── persona.md         # 人设、说话位置、文风
├── prompts/           # 覆盖/补充通用提示词（可选）
├── angles.md          # 角度库
└── templates/         # 卡片 HTML/CSS 模板
```

## 5. 非功能需求

### NFR-1 成本

- LLM：DeepSeek API，全流程每日 token 消耗 ≤ 5 万（约 0.1-0.2 元/天），月成本 < 10 元；
- 月度预算告警阈值：30 元（超限推送通知并暂停自动成文）；
- 成图零成本（本地渲染）。

### NFR-2 合规与安全

- 敏感话题自动拦截：政治、社会争议、医疗健康、法律金融建议等高风险分类不进候选池；
- AI 参与生成的内容发布时按平台规则标注；
- 版权：AIHOT 与第三方内容仅作选题灵感与事实引用，正文观点原创；引用数据/事件列来源；不搬运图文；
- AIHOT 授权：初期按「选题灵感来源」使用；规模化商业变现前书面申请授权；
- 事实铁律：无源事实零容忍；关键事实必须有来源或 `[待查证]`，绝不编造；
- 凭据不入库、不入文档：DeepSeek Key、PushPlus Token 走环境变量或本地 `.env`（gitignore）。

### NFR-3 可测试性

- 回归测试库：`tests/`，用固定 fixture（含 AIHOT 样例数据）覆盖每个阶段；
- 提示词升级、代码重构必须通过回归测试；
- LLM 调用在测试中可 mock（固定输入输出快照）。

### NFR-4 文档先行

- 需求文档、架构文档、接口文档三件套与代码同步维护；
- 接口变更必须同步更新接口文档。

### NFR-5 可迁移

- v1 本地 Windows；v2 迁移服务器时只改部署层（调度、进程管理、域名），代码与数据文件可整体搬移；
- 服务器约束（已调研）：腾讯云轻量 4C4G，Java+MySQL 已占用大部分内存，Python 服务需限内存（目标 RSS < 300MB），独立 localhost 端口 + Caddy 子域名，数据用 SQLite 不用 MySQL。

## 6. 版本范围

### v1（本期）

- 本地 Windows 运行；AIHOT + 补充源；五维评分；审核界面（局域网 + 内网穿透）；DeepSeek 单次成文 + 内置调研；事实账本；HTML 模板成图；手动发布；PushPlus 通知；Windows 任务计划；多领域框架（先只启用 ai-tools）；回归测试库。

### v2（后续）

- 服务器部署（systemd + Caddy 子域名 + 内存限制）；半自动发布；小红书站内验证；混合模型（DeepSeek 跑量 + 强模型成文）；LangGraph 多 Agent 编排；AI 生图装饰层；更多领域启用。

## 7. 验收标准（v1）

1. 用真实数据跑通一次完整闭环（候选 → 审核 → 成文 → 润色 → 成图 → 发布包）；
2. 连续 7 天自动采集无人工干预失败；
3. 审核界面在手机浏览器可用，含候选审核、批注、确认、下载；
4. 产出的小红书笔记满足：无编造事实、无 AI 腔（通过去 AI 味自检）、观点中立且有共情；
5. 回归测试全绿。
